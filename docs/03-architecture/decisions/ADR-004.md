# ADR-004: SHA-256 Artifact Integrity

**Document ID:** ADR-004  
**Title:** Selection of SHA-256 as Standard Artifact Digest Algorithm  
**Status:** APPROVED  
**Deciders:** Security Architect, Cryptographer, Extension Engineer  
**Date:** 2026-11-09  

---

## 1. Context and Problem Statement
Which cryptographic hash function should LUCENTRA mandate for generating unique digests of web JavaScript resources and release manifests?

---

## 2. Decision Drivers
- Ubiquitous hardware-accelerated support across browser runtimes (`crypto.subtle.digest`).
- Compatibility with Web Standards (W3C Subresource Integrity).
- Cryptographic security margin against collision and pre-image attacks.
- High hashing throughput in Web Workers.

---

## 3. Considered Options
- **Option 1:** Keccak-256 (Native EVM).
- **Option 2:** SHA-384 / SHA-512.
- **Option 3:** SHA-256 (NIST FIPS 180-4).
- **Option 4:** BLAKE3.

---

## 4. Decision Outcome
**Chosen Option:** **Option 3: SHA-256 (NIST FIPS 180-4).**

All JavaScript files and the canonical release manifest are hashed using SHA-256. Digests are formatted as lowercase hex strings prefixed with `sha256:`.

### Consequences
- **Positive:** Supported natively by Web Cryptography API (`crypto.subtle.digest("SHA-256", ...)`) in all browsers without third-party WASM libraries; universally compatible with SRI.
- **Negative:** Keccak-256 is cheaper inside EVM contracts, but SHA-256 is precompiled at address `0x02` on Ethereum and costs only 60 gas plus 12 gas per word.

---

## 5. Security Implications
SHA-256 provides 128-bit collision resistance and 256-bit pre-image resistance, well exceeding requirements for web asset integrity.
