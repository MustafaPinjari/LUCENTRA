# ADR-002: Publisher Identity through Wallet and DNS Verification

**Document ID:** ADR-002  
**Title:** Dual-Anchor Publisher Identity via DNS TXT and EVM Wallet  
**Status:** APPROVED  
**Deciders:** Security Architect, Product Architect, Blockchain Engineer  
**Date:** 2026-11-09  

---

## 1. Context and Problem Statement
How does LUCENTRA securely and trustlessly bind a conventional web domain name (e.g. `uniswap.org`) to an Ethereum address without requiring changes to the global DNS protocol or domain registrar infrastructure?

---

## 2. Decision Drivers
- Zero changes to existing global DNS protocols.
- Proof of authoritative domain control.
- Elimination of domain spoofing or unauthorized key claims.
- Support for key rotation and revocation.

---

## 3. Considered Options
- **Option 1:** Well-known HTTPS file challenge (`/.well-known/lucentra.json`).
- **Option 2:** DNS TXT record challenge (`_lucentra-verification.<domain>`).
- **Option 3:** Pure ENS (Ethereum Name Service) delegation.

---

## 4. Decision Outcome
**Chosen Option:** **Option 2: DNS TXT Record Challenge.**

Publishers prove domain ownership by creating a DNS TXT record at `_lucentra-verification.<domain>` containing a cryptographically secure 256-bit challenge token issued by the backend. Once validated by querying authoritative nameservers, the publisher executes an on-chain registration linking their Ethereum wallet address to `keccak256(domain)`.

### Consequences
- **Positive:** Leverages existing DNS administrative infrastructure; immune to simple HTTP reverse proxy or CDN edge compromises.
- **Negative:** Requires publisher access to DNS management portal.

---

## 5. Security Implications
DNS TTLs must be accounted for. Challenge tokens must have short lifespans (e.g. 24 hours) and high entropy (256 bits) to prevent brute-force attacks.
