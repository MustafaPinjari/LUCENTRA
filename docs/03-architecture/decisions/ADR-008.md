# ADR-008: Chrome Manifest V3 Architecture

**Document ID:** ADR-008  
**Title:** Chrome Extension Architecture Conformance to Manifest V3  
**Status:** APPROVED  
**Deciders:** Extension Engineer, System Architect, Security Architect  
**Date:** 2026-11-09  

---

## 1. Context and Problem Statement
Google Chrome has deprecated Manifest V2. All modern browser extensions must use Manifest V3, which introduces strict sandboxing, replaces persistent background pages with ephemeral service workers, and restricts dynamic code execution.

How does LUCENTRA implement high-performance DOM script inspection and cryptographic hashing within Manifest V3 constraints?

---

## 2. Decision Drivers
- Chrome Web Store acceptance and Manifest V3 compliance.
- Non-blocking cryptographic hashing of large JavaScript assets.
- Fast, non-intrusive UI badging.

---

## 3. Considered Options
- **Option 1:** Attempt deprecated Manifest V2 patterns (Guaranteed store rejection).
- **Option 2:** Monolithic Content Script Execution (Blocks the UI thread during hashing).
- **Option 3:** Decoupled MV3 Architecture: Content Script (DOM interception) + Dedicated Web Worker (SHA-256 calculation) + Service Worker (State & EAS verification).

---

## 4. Decision Outcome
**Chosen Option:** **Option 3: Decoupled MV3 Architecture.**

- Content script attaches a `MutationObserver` at `document_start`.
- Dispatches script URLs to a dedicated Web Worker that computes SHA-256 hashes via `crypto.subtle`.
- Background service worker maintains attestation cache in `chrome.storage.local` and manages tab badge updates.

### Consequences
- **Positive:** Zero main thread jank; fully compliant with Chrome MV3 policies; clean security boundaries.
- **Negative:** Requires handling service worker inactivity and termination gracefully.

---

## 5. Security Implications
Strictly enforces `script-src 'self'` in extension CSP. No dynamic code evaluation (`eval()` / `new Function()`) permitted.
