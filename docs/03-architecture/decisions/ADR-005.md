# ADR-005: JSON Canonicalization Scheme (RFC 8785)

**Document ID:** ADR-005  
**Title:** Adoption of RFC 8785 (JCS) for Deterministic Manifest Serialization  
**Status:** APPROVED  
**Deciders:** Protocol Architect, Backend Engineer, Frontend Engineer  
**Date:** 2026-11-09  

---

## 1. Context and Problem Statement
JSON objects are inherently unordered. Different programming languages, JSON serializers, and platforms format JSON with varying whitespace, key ordering, and numerical notation. 

If publisher tooling, backend APIs, and browser extensions do not serialize the manifest identically, computing `SHA-256(manifest_json)` will produce completely different hashes, causing cryptographic signature verification to fail.

---

## 2. Decision Drivers
- 100% deterministic, cross-language serialization (TypeScript, Python, Go).
- Elimination of signature malleability due to whitespace or key ordering.
- Conformance to established IETF standards.

---

## 3. Considered Options
- **Option 1:** Custom deterministic JSON serializer (ad-hoc sorting).
- **Option 2:** Protocol Buffers / ASN.1 / CBOR.
- **Option 3:** IETF RFC 8785: JSON Canonicalization Scheme (JCS).

---

## 4. Decision Outcome
**Chosen Option:** **Option 3: IETF RFC 8785 (JCS).**

LUCENTRA mandates that all release manifests must be transformed into canonical form using RFC 8785 before computing the root `manifestHash`.

### Consequences
- **Positive:** Standardized, battle-tested specification with compliant libraries in TypeScript (`canonicalize`), Python (`canonicaljson`), and Go (`go-jcs`).
- **Negative:** Requires rigorous compliance testing across all client and backend runtimes.

---

## 5. Security Implications
Prevents signature invalidation and prevents attackers from manipulating key order or whitespace to bypass hashes.
