# ADR-006: Ethereum Publisher Registry

**Document ID:** ADR-006  
**Title:** Decentralized Domain-to-Key Registry Smart Contract (`PublisherRegistry.sol`)  
**Status:** APPROVED  
**Deciders:** Blockchain Engineer, System Architect, Security Architect  
**Date:** 2026-11-09 (Updated: 2026-11-09)  

---

## 1. Context and Problem Statement
Where should the authoritative, tamper-proof mapping between normalized web domain names and publisher Ethereum addresses be maintained, and who should possess authority to create records and manage signing keys?

---

## 2. Decision Drivers
- Decentralized, censorship-resistant public access.
- Elimination of arbitrary public domain claims.
- Non-custodial publisher key ownership and rotation.
- Atomic key revocation capabilities.
- Minimal gas overhead on EVM networks.

---

## 3. Considered Options
- **Option 1:** Centralized database table as root of truth.
- **Option 2:** Publicly callable smart contract using relayed signature tickets.
- **Option 3:** Dedicated EVM Smart Contract (`PublisherRegistry.sol`) with Authorized Registrar for initial registration and Owner Sovereignty for key lifecycle.

---

## 4. Decision Outcome
**Chosen Option:** **Option 3: Dedicated Smart Contract with Registrar Initial Binding & Owner Key Governance.**

- `registerDomain(domain, owner)` is restricted strictly to `onlyRegistrar`.
- `authorizeKey` and `revokeKey` are restricted strictly to `onlyDomainOwner(domain)`.

### Consequences
- **Positive:** Publicly auditable on-chain; immune to public claim front-running; publisher retains full self-custody over signing-key rotation and revocation.
- **Negative:** Requires registrar operational key maintenance.

---

## 5. Security Implications
Registrar cannot seize or re-assign already registered domains. Publisher keys can execute immediate emergency revocation at any time.
