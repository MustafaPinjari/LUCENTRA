# ADR-006: Ethereum Publisher Registry

**Document ID:** ADR-006  
**Title:** Decentralized Domain-to-Key Registry Smart Contract (`PublisherRegistry.sol`)  
**Status:** APPROVED  
**Deciders:** Blockchain Engineer, System Architect, Security Architect  
**Date:** 2026-11-09  

---

## 1. Context and Problem Statement
Where should the authoritative, tamper-proof mapping between normalized web domain names and publisher Ethereum addresses be maintained?

---

## 2. Decision Drivers
- Decentralized, censorship-resistant public access.
- Non-custodial key ownership.
- Atomic key revocation and rotation capabilities.
- Minimal gas overhead on EVM networks.

---

## 3. Considered Options
- **Option 1:** Centralized PostgreSQL database table.
- **Option 2:** Ethereum Name Service (ENS) Text Records exclusively.
- **Option 3:** Dedicated EVM Smart Contract (`PublisherRegistry.sol`).

---

## 4. Decision Outcome
**Chosen Option:** **Option 3: Dedicated EVM Smart Contract (`PublisherRegistry.sol`).**

The contract stores `mapping(bytes32 => DomainRecord)` where the key is `keccak256(bytes(normalizedDomain))`. The record stores the owner address, authorized signing keys, registration timestamps, and revocation flags.

### Consequences
- **Positive:** Publicly auditable; independent of any corporate server; allows instant, on-chain key revocation.
- **Negative:** Requires gas for domain registration and key management.

---

## 5. Security Implications
Domain registration requires cryptographic proof of DNS verification signed by the backend validator service to prevent domain squatting. Owner keys can execute emergency revocation at any time.
