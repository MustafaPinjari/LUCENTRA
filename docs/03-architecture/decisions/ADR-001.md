# ADR-001: Hybrid Web2/Web3 Architecture

**Document ID:** ADR-001  
**Title:** Hybrid Web2/Web3 Architecture Topology  
**Status:** APPROVED  
**Deciders:** Chief Technology Architect, System Architect, Security Architect  
**Date:** 2026-11-09  

---

## 1. Context and Problem Statement
LUCENTRA requires high-performance, real-time client verification (sub-150ms latency) across millions of web page loads, combined with tamper-proof, censorship-resistant publisher identity and release attestation guarantees.

A pure Web2 centralized architecture introduces a single point of failure and makes the central server a lucrative target for compromise. Conversely, a pure Web3 on-chain architecture (storing all manifest JSON on Ethereum and querying RPC on every page load) introduces prohibitive gas costs and high network latency.

---

## 2. Decision Drivers
- Real-time client verification latency budget ($\le 150\text{ ms}$).
- Elimination of centralized trust: Server compromise must not allow forged releases.
- Cost feasibility: Avoid high gas costs for large JSON manifests.
- High availability: System must remain verifiable even if central API experiences an outage.

---

## 3. Considered Options
- **Option 1:** Pure Centralized Web2 (PostgreSQL API as sole truth).
- **Option 2:** Pure On-Chain Web3 (All manifests stored on Ethereum L1/L2 contracts).
- **Option 3:** Hybrid Web2/Web3 Architecture (On-chain identity/attestation anchor + Off-chain cached manifest serving + Client-side verification).

---

## 4. Decision Outcome
**Chosen Option:** **Option 3: Hybrid Web2/Web3 Architecture.**

- On-chain: `PublisherRegistry.sol` (domain-to-key binding) + EAS (release digest attestation).
- Off-chain: Django REST API + Redis (metadata caching and witness aggregation).
- Client-side: Chrome Extension verifies cryptographic signatures directly.

### Consequences
- **Positive:** Sub-100ms response times for manifest delivery; zero gas cost for manifest queries; decentralized cryptographic truth guarantees.
- **Negative:** Increased architectural complexity spanning both Web2 and Web3 stacks.

---

## 5. Security Implications
Even if the Django API database is completely breached, an attacker cannot forge publisher release signatures or falsify on-chain EAS attestations. The client extension cross-checks the cryptographic root hash directly.
